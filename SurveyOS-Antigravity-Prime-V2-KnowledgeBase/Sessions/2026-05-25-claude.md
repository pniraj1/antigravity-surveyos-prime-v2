### Project Bramha: Archive-Trigger Redesign
**Design decisions made (brainstorming session):**
- Bramha writes to `bramha_memories` ONLY when a claim is archived (`isActive: false`), NOT on `isCompleted` toggle
- Claims can only be archived when `isCompleted === true` (client-side gate)
- Embedding text includes: vehicle + damage assessment + accident location (uses existing `placeOfAccident` field)
- `bramha_memories` metadata supports 3 intelligence modes:
  1. **RAG** — vector similarity search for damage patterns (via `FieldValue.vector()`)
  2. **Fraud Detection** — exact Firestore queries on policyNumber, vehicleRegistration, customerPhone
  3. **Civic/Hotspot** — location aggregation on `placeOfAccident`
- PII stored in metadata fields only (not embedded into vector text)
- Spec: `docs/superpowers/specs/2026-05-25-bramha-archive-trigger-design.md`
- Plan: `docs/superpowers/plans/2026-05-25-bramha-archive-trigger.md`

## Key Architecture Notes for Next Agent

### Claim Lifecycle (UPDATED)
```
isActive: true, isCompleted: false  →  Active, in-progress
isActive: true, isCompleted: true   →  Active, done (ready to archive)
isActive: false, isCompleted: true  →  Archived → TRIGGERS Bramha embedding
```
Archiving incomplete claims is now blocked at UI level in both Dashboard.tsx and NewClaimDialog.tsx.

### Bramha Cloud Function Location
- Source: `SurveyOS-Prime/functions/bramha.js` (NOT inside SurveyOS-Prime-V2)
- Firebase project: `surveyos-v2-antigravity`
- Function name: `onClaimArchived` (us-central1)
- Reads Gemini API key from Firestore: `ai_config/routing` → `providers[name=gemini].keys[0]`
- Writes to: `bramha_memories` collection (root-level, shared across all surveyors)

- Stores: claimMeta, claims, tombstones, pushedAt, driveFileCache (NEW)
